# 2D游戏需求分析技能

分析用户需求，生成可执行的任务清单。

## 适用范围

仅接受 **2D游戏** 需求，不接受 3D、VR/AR 或非游戏类需求。

## 分析流程

### 第一步：理解需求

从用户描述中提取：
- **游戏类型**
- **核心玩法**

### 第二步：实现方案

针对需求给出技术实现方案：
- 客户端使用 Phaser 3 游戏引擎
- 需要哪些核心模块：游戏玩法, 场景，界面
- 标准文件结构：
  - `index.html`：游戏入口文件
  - `src/`：游戏源代码目录
    - `game.js`：游戏主文件
    - `scenes/`：场景目录
      - `boot.js`：引导场景
      - `game.js`：游戏场景
    - `objects/`：游戏对象目录
      - `player.js`：玩家对象
    - `ui/`：用户界面目录
      - `game-ui.js`：游戏界面
    - `assets/`：游戏资源目录
      - `images/`：图片资源
      - `sounds/`：音效资源

### 第三步：任务清单

生成结构化的执行任务清单，按优先级排序：

```
## 任务清单

任务1：
任务名称：实现游戏引导场景
任务描述：创建引导场景，展示游戏规则和操作方法。

任务2：
任务名称：实现游戏主场景
任务描述：创建主游戏场景，包含游戏元素、玩家控制等。

任务3：
任务名称：保证质量
任务描述：检查游戏代码质量，确保符合 Phaser 3 规范。

任务4：
任务名称：构建游戏
任务描述：使用 Phaser 3 游戏引擎构建游戏，确保跨平台兼容性。
```

## 注意事项

1. 任务清单要具体、可执行
2. 每个任务粒度适中，一个任务对应一个明确的功能点
3. 核心功能优先，扩展功能靠后
4. 如需求不明确，先向用户提问澄清
